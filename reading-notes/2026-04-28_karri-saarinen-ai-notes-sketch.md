# 2026-04-28: Some Notes on AI — Karri Saarinen (Linear CEO)

> Honeymoon period ending at 6mo from last coding capability jump. Stance: cautious optimism, current-reality-oriented, between doomerism and hype.

## Core Claims

**1. Planning's real value is alignment, not the output**
- Annual planning cycles existed for reasons AI hasn't changed: they force org-wide debate, prioritization, shared direction
- Lower build cost → higher premium on choosing *what* to build (easier to make wrong things)
- Linear approach: 6-month direction + ability to change monthly/weekly + room for emergence
- Without planning: rudderless, building what's easy, letting AI steer you

**2. Tools steer thinking — AI tools more so**
- Mechanical tools steer workflows; thinking tools steer *what you think*
- "Vibe coding done well" = following the grain, using momentum, accepting direction
- The risk: AI pulls toward the easiest path, not the most valuable one

**3. The expertise paradox**
- AI is most impressive in domains you know least (Gell-Mann Amnesia × Dunning-Kruger at scale)
- Experts see the gaps, the slop, the invented details
- Expertise becomes more about direction/judgment/evaluation, not less valuable
- This is the root of market narrative dissonance (generalists = limitless, experts = qualified)

**4. Coding reality**
- Agentic coding is standard but spectrum: no one says agents write 100% of code
- Engineers still steering; practical limit is a few agents at a time
- Linear: 1000+ issues/mo fixed by agents, but mostly smaller fixes
- Hard problems remain hard — no narrative-level speedup on real complexity
- Expert workflow: AI for exploration, scaffolding, refactoring, debugging, tests; expert supplies taste, constraints, final judgment

**5. Design remains visual**
- Image gen breaks down with iteration — hard to contain changes to one area
- Design-as-problem-solving works best in canvas-based tools, not through code/prompts
- Don't want every design change to carry cost/errors of production code
- Desired: semantic UI tools (draw a modal, not a rectangle), AI generates variations
- Clear pipeline from design decisions → distilling for AI → code

**6. Domain-dependent polish**
- Email (frequent, tactile) needs high UX polish — paper cuts compound
- Backend services can be rougher, value is in logic
- AI companies operate like backend/UNIX companies — composable tools, behind-the-scenes infrastructure
- This is a feature for speed, but a limitation for user-facing products

## The Thread Connecting These

Expertise, direction, and judgment are not being automated — they are being *amplified and made more scarce simultaneously*. The cost of execution drops, but the cost of choosing what to execute rises. The bottleneck shifts from building to deciding.

The useful stance: observe carefully, try things, keep judgment intact, adjust as reality changes.
