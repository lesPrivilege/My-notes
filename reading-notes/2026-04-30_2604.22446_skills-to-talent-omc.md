# From Skills to Talent: Organising Heterogeneous Agents as a Real-World Company

- **来源**: https://arxiv.org/pdf/2604.22446
- **日期**: 2026-04-24
- **作者/机构**: Zhengxu Yu, Yu Fu, Zhiyuan He, Yuxuan Huang, Lee Ka Yiu, Meng Fang, Weilin Luo, Jun Wang — HUAWEI Noah's Ark Lab, UCL, University of Liverpool
- **类型**: paper
- **置信度**: high (HTML version from arXiv, all sections readable)
- **模式**: deep-review

## 核心问题

現有的 multi-agent 系統被困在靜態團隊結構、緊耦合協調邏輯、以及 session-bound 學習之中。它們缺乏一個原則性的組織層（organisational layer），讓異質 agent 的工作力可以被動態組合、治理、並隨時間改善——這與單一 agent 的能力進步脫節。

## 核心方案

1. **Talent–Container Architecture** — 將 agent 的身份（Talent：prompts、skills、tools、工作原則）與執行環境（Container：LangGraph、Claude CLI、script）徹底分離。Talent 是可移植的"員工檔案"，透過六個 typed organisational interfaces（execution/task/event/storage/context/lifecycle）與 Container 溝通，使異質 runtime 可在統一的管理層下協作。

2. **Explore-Execute-Review (E²R) Tree Search** — 將專案執行建模為組織策略空間中的搜索。Explore 階段動態分解任務樹，Execute 透過 DAG-based 排程分派給員工，Review 階段以 completed→accepted gate 確保品質。提供 termination 和 deadlock-freedom 的形式化保證（AND-tree semantics + finite state machine）。

3. **Talent Market** — 社群驅動的 agent marketplace，提供 verified open-source agents，支持 on-demand 招聘。HR agent 自動查詢市場、compile shortlist、CEO 批准後 provisioning。冷啟動問題透過 AI-powered recommendation engine 從 web 發現技能來緩解。

4. **Self-Evolution 機制** — 三層回饋迴路：individual level（CEO one-on-ones + post-task reflection 更新 agent 的工作原則）、project level（retrospectives 提煉 SOPs）、organisation level（定期績效評估、PIP、自動 offboarding）。

## 證據

**PRDBench 定量結果（50 個 project-level 軟體開發任務）：**

| Method | Success Rate (%) | Cost ($) |
|--------|:-:|:-:|
| GPT-5.2 (single) | 62.49 | - |
| Claude-4.5 (single) | 69.19 | - |
| Gemini-3-Pro (single) | 22.76 | - |
| Qwen3-Coder (single) | 43.84 | - |
| CodeX (commercial) | 62.09 | - |
| Claude Code (commercial) | 56.65 | - |
| **OMC (ours)** | **84.67** | **345.59** |

- OMC 超越所有 baseline，SOTA 提升 **15.48 百分點**
- 每 task 平均成本約 **$6.91**，baseline 成本未公開，無法直接比較 cost-efficiency
- 模型組合：Claude Code Sonnet 4.6 + Gemini 3.1 Flash Lite Preview（更早的 Gemini 2.1 Flash Lite Preview 用於 founding agent）

**四大跨域 case study（定性）：**
1. **Content generation** — GPT-4o + Claude Sonnet 4 協作 GitHub trend report，10 分鐘、$4.48，所有 repo links 手動驗證屬實
2. **Game development** — Claude Sonnet 4 + Gemini 2.5，human-in-the-loop feedback 驅動 sprite sheet bug 修復，系統自動為 Art Designer 新增 skill
3. **Audiobook production** — Gemini 3.1 Pro 跨模態（text→script→image→TTS→video），16 scenes + 16 voice-over tracks + background music，$1.57
4. **Automated research survey** — Claude Sonnet 4.6 + self-hosted agent，從一句 prompt 到 17 份文檔 + mind map + 3 個 grounded research ideas，$16.26、<1 小時

## 風險與弱點

- ⚠️ **定量評估範圍狹窄** — 僅 PRDBench（50 tasks coding benchmark），non-coding benchmarks 尚缺。雖然 case studies 展示了跨域適用性，但這些是展示性而非系統性比較。
- ⚠️ **Self-evolution 未 ablation** — one-on-ones、retrospectives、performance reviews 已實作但尚未量化各機制的貢獻度。作者的確承認需要 longitudinal studies。
- ⚠️ **成本可比性問題** — baseline 成本未報告，"$6.91 per task" 無法與單一 agent 方案直接比較。對於簡單任務，multi-agent coordination overhead 很可能浪費。
- ⚠️ **CEO 仍需參與 hiring 決策** — case study 中提到"the only human involvement... selecting employees from the HR-compiled candidate shortlist"。這不是 fully autonomous。
- ⚠️ **Talent Market 的 cold-start 依賴** — 依賴社群貢獻 verified agents；AI recommendation engine 雖可緩解但不確定效能。Marketplace 需要 network effect 才能自我維持。
- ⚠️ **Multi-agent 系統的通用風險** — 多層 LLM 調用疊加 error propagation（儘管 review gate 設計試圖控制）、延遲累積、以及非確定性行為在更大規模時的影響未探索。

## 待驗證問題

1. E²R tree search 的 termination/deadlock-free guarantees 在極大規模（數百 agent）時能否維持？
2. Talent–Container 的 typed interfaces 覆蓋所有 real-world agent runtime 的可能性——每新增一個 backend（如 OpenAI Agents SDK）需要多少 adapter 工作？
3. Self-evolution 是否會導致 SOPs 的 over-specialization（學到只有特定 task 有效的模式並固化）？還是真的通用改善？
4. 與 SWE-bench 等既有 benchmark 的比較如何？PRDBench 是 2026 年新 benchmark，缺乏獨立驗證。

---

**核心判斷**：OMC 的組織層抽象（Talent/Container/E²R/organisational interfaces）是對 multi-agent 系統設計空間的一個有意義的貢獻。Talent 作為"可移植 agent 身份"的抽象層級高於既有 skills/tools 抽象，概念上乾淨。E²R tree 的形式化保證（termination + deadlock-freedom）在實務系統中少見，值得關注。主要疑慮在於：定量證據僅來自一個新 benchmark，self-evolution 的實際 impact 尚不明確，且開放式問題（scalability、marketplace network effect、跨域泛化）多於已解答的問題。
