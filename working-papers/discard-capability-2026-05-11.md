# 丢弃函数：信息筛选的架构放置与时效失效

> Working Paper · Draft · 2026-05-11
> Revised · 2026-05-20
> Source notes: 12 original entries from tech.md + mind.md; updated against 2026-05-16/05-20 index

---

## 主张

智能系统的核心竞争力不只取决于「模型能处理多少信息」，也取决于「模型在何处、何时、按什么判据决定不处理什么」。在 tokenization、attention、FFN 激活、缓存策略、推理调度、世界模型表征等抽象层中，信息筛选机制正在成为系统效率与泛化边界的共同变量。

2026-05-20 的 `compile-economy` paper 已经把「能离线解决的不要在线解决」发展为编译经济学框架：离线化、剧本化、缓存、垂直编译层的核心问题是成本判准与重编译频率。因此本文不再把离线/在线作为主轴，而将其视为丢弃函数的一种背景机制。本文的独立问题是：丢弃函数应放在架构哪一层？多层丢弃之间如何协调？当任务分布变化后，原本正确的丢弃规则如何失效、检测和重编译？

---

## 论据链

### E1. 离线/在线原理作为背景机制

> *来源：tech.md ——「能离线解决的问题不要在线解决」是跨抽象层的统一原理*

从 over-training 把高频 pattern 烧进权重、到 MoE 稀疏激活只调动相关 expert、到 KV cache 命中避免重复 prefill、到 system prompt caching 最大化前缀复用、到 TwELL 的 FFN activation sparsity——每一层都在做同一件事：把重复计算前置，运行时只处理增量。这不是工程巧合，是 memory bandwidth 作为硬瓶颈决定了所有抽象层的优化方向必然趋同。

但这个观察已经被 `compile-economy-2026-05-20` 更完整地展开为「编译效率」问题：把在线推理下沉为离线系统是否划算，取决于开发成本、边际推理成本、分布漂移后的重编译成本。对本文而言，离线化不是终点，而是丢弃函数的一种形式：系统预先判定哪些状态、路径、信息不值得在运行时重新计算。

**论据功能**：背景奠基。保留跨层普遍性，但把主问题从「为什么离线化」移到「丢弃函数如何被放置和维护」。

### E2. 固化的边界与分层调度

> *来源：tech.md —— 固化的粒度取决于任务空间维度和上下文变异度的乘积；剧本化、缓存、实时决策是按风险等级分层调度的*

不是所有任务都可以离线固化。边界条件有两个维度：任务空间是否可穷举（pipeline 级调度），上下文是否高度变异（per-session 调度）。Pope 的贡献是给了后者一个物理度量——KV cache 大小与 memory bandwidth 的比值。

实际部署架构是分层的：低风险用缓存（直行巡航），中等风险用预编译剧本（标准变道），高风险才用完整模型推理。大部分运行时间花在前两层。任务空间真正可穷举时，确定性代码优于模型；当穷举成本超过训练成本时，权重就是更经济的剧本存储方式。

这一路径现在需要补上时效维度：固化不是一次性决策，而是对某个任务分布的压缩。任务分布变化后，原本节省计算的丢弃规则会变成错误过滤器。于是分层调度不只是「哪些事情该离线」，还包括「哪些离线规则已经过期」。

**论据功能**：理论细化。给出离线/在线的边界条件，并引出丢弃函数的动态失效问题。

### E3. 模型内部的自发筛选机制

> *来源：tech.md —— Activation sparsity 是模型内部的自发丢弃函数；Token 化之前完成信息筛选的三条路径* 

LLM 内部存在两条信息筛选路径。第一条是 FFN 层的 activation sparsity：TwELL 发现 LLM FFN 层在 99.5% sparsity 下性能几乎不变（5632 neuron 中只激活约 28 个）。Token 级分析确认丢弃是内容敏感的——高信息 token 激活远多于低信息 token，序列起始位置激活远高于后续。这比人的感官预过滤更灵活（视网膜结构固定），比全精度 attention 更高效。

第二条发生在 tokenization 阶段：Learned routing（adaptive patch resolution）、retrieval gate（可微分门控编码相关性）、information-theoretic tokenization（按 surprisal 分配粒度）。三者共同点是把筛选从 O(n²) 的 attention 前移到线性或亚线性的硬分配。

关键未知：复杂推理是否需要更多 neuron 协同激活。若是，99.5% sparsity 可能是已编译任务的特权而非通用特性，效率-泛化权衡在此处再现。同样，筛选决策需要对下游任务有预判，但 tokenization 阶段信息不完整，gradient 如何穿过离散的 drop-or-keep 决策仍是开放问题。

**论据功能**：实证支撑。展示模型内部已有的两种自发筛选机制及其效率边界。

### E4. 丢弃函数的架构放置

> *来源：mind.md —— 丢弃函数是能力构成差异的根源，不是数据量或参数量；tech.md —— 丢弃函数的架构放置是世界模型的核心设计变量*

人的丢弃函数是进化硬编码的（视网膜中央凹 2°、周边视野对运动敏感），高效但不灵活。模型的丢弃函数是训练软学来的，灵活但昂贵。当前架构创新（primitive tokenization、JEPA 拒绝 decoder、KV 压缩、TwELL sparsity）本质上都在给模型装更好的丢弃函数。

2026-05-16 的新条目把问题推进了一步：核心不再是「要不要丢弃」，而是「丢弃函数放在架构的哪一层」。不丢弃，能源约束不允许持续全精度 attention；丢弃到人类同构程度，机器相对于人的结构性优势（并行、不疲劳、跨模态带宽）又会退化。DeepSeek 在编码器层压缩，JEPA 在表征层拒绝 decoder，TTT 在推理层按需适应，这些方案各守一层，但缺少层间协调协议。

因此，丢弃函数不应是单点模块，而应是分布在多层的级联结构——硬件粗筛 → 编码器压缩 → 表征层抽象 → 注意力动态分配 → 推理层按需调用。人的感知系统恰好是这种级联（视网膜 → V1/V2 → 腹侧/背侧通路 → 前额叶注意力调控），每层粒度和灵活性不同。机器世界模型如果要在能源可行性和超人优势之间找到位置，需要的不是选择某一层放丢弃函数，而是设计层间的丢弃协调协议。

硅基系统的效率-泛化权衡不可同时最大化（mind.md）：不丢弃，能源撑不住（物理约束）；全丢弃等同人类系统，放弃了做机器的理由。模块化的效率来自隔离，泛化的能力来自耦合。模块间的接口本身就是一种丢弃函数——跨接口传递的信息必经格式化和压缩。科幻式全能 AGI 在效率-泛化二维不可同时最大的前提下，大概率是不可达的点。

**论据功能**：核心论证。将本文从一般信息筛选框架推进到架构设计问题：丢弃函数的位置、粒度、层间协议决定系统边界。

### E5. 离散化边界的损失统一框架

> *来源：mind.md —— 离散化边界的信息损失是所有范式天花板的统一结构*

任何系统为了可操作性而引入的离散化边界，都会在边界处产生不可逆的信息损失，该损失在该范式内无法消除。LLM 的 tokenization、组织架构的分工、学科划分、法律条文化、代数操作的符号化，都是同一个结构的实例。

科学进步很大程度上是在重新缝合前一代人切出来的边界，但缝合本身又引入新的切分。范式转换不是消除信息损失，而是选择在不同的位置承受它。这是对 E4 中效率-泛化权衡的元层次解释：丢弃不是可优化的性能参数，而是系统存在的必然代价。

**论据功能**：元框架。为整篇论文的论证提供认识论层次的基础——丢弃不是可选的，是必然的。

### E6. 丢弃函数的动态失效

> *来源：tech.md —— HL 的维护成本是转移而非消除；分布漂移触发重编译频率；缓存调度类比预测的失效问题；mind.md —— LLM 缺少独立于内容的元信息层*

翁的 HL 主张过去规则系统死于维护成本、coding agent 能承担。但实际含义是「LLM 处理耦合交互的能力比人类工程师强」——这是需要验证而非假设的命题。目前实验 policy 都在几百行量级，没有触及传统 rule-based 系统崩溃时的规模。三层混合架构（NN 感知 + HL 规则 + LLM 审查）的层间接口是动态耦合而非静态分层。

5/20 的新 index 把这个问题改写为动态性缺口：HL、缓存、垂直编译层本质上都是对当前任务分布的压缩；当分布漂移时，缓存会失效，剧本要重编译，丢弃函数也会过期。一个原本正确的筛选器，在新分布下可能系统性丢掉关键变量。丢弃函数的风险因此不是「丢太多」这么简单，而是「曾经该丢的东西后来不该丢」。

更深层的结构性限制：Transformer 的 attention 在内容上做匹配——没有内容就没有 attention，没有 attention 就没有检索。人的记忆本质上是索引系统——存储在外部，人脑保留多模态检索线索（场景、情绪、空间位置的交叉索引）。更长 context 或更好压缩不会自动产生「不记得内容但知道去哪找」的能力。翁的 HL 中 tests/replays/version diffs 的显式保存，本质上是在系统架构层面手工外挂这个索引系统——但这是一个外在补丁，不是模型内生的元能力。

**论据功能**：限定条件与开放问题。展示当前方案的实际边界，并把维护成本具体化为丢弃规则的失效检测与重编译问题。

## 已知弱点

### W1. 跨层级级联的工程可行性未知

- **严重程度**：高
- **说明**：E4 提出丢弃应分布在多层的级联结构，但当前无任何系统实现跨层协调的丢弃。每层（tokenizer、attention、FFN、world model、runtime policy）独立设计，无全局 loss 函数、端到端优化目标或层间丢弃协议。本文主张人有这种级联（视网膜 → V1 → 通路的映射精确），但不代表当前架构下这个映射是可训练的——人脑的级联是演化逐步叠加的，不是一次设计的。ML 系统每个组件都是端到端可微的，强行插入离散丢弃门会切断梯度。

### W2. 效率-泛化权衡的连续性被低估

- **严重程度**：中
- **说明**：论证（E4）说效率与泛化不可同时最大化，边界是离散二选一。但 TwELL 的 99.5% sparsity 同时提升了计算效率和有限泛化——这暗示边界可能不是清晰权衡而是平滑谱系。关键区别是：是「泛化完全不损失直到某个 threshold 然后崩塌」还是「泛化随效率线性递减」？当前证据指向前者（threshold 行为），但论证中没有明确讨论这个形状。

### W3. 主要实证来自单一领域

- **严重程度**：中
- **说明**：跨层级统一原理（E1）的实证支撑集中在 ML 系统内部（over-training、MoE、KV cache、TwELL、prompt caching）。外部领域（生物感知系统的 energy budget、资本市场的信息筛选、免疫系统的抗原呈递）的证据是类比而非严格映射。E5 的元框架暗示这些外部领域也服从同一结构，但缺乏结构化的比较论证。

### W4. 离散化边界框架的自指困境

- **严重程度**：低
- **说明**：E5 主张离散化边界的信息损失是所有范式天花板的统一结构。但本文本身也引入了离散化边界——把连续的系统设计空间切成「离线/在线」「效率/泛化」「丢弃/保留」的二元对立。按 E5 自己的逻辑，这种切分也有信息损失，可能在边界处遗漏了真正重要的结构。

### W5. 丢弃函数的时效性缺口

- **严重程度**：高
- **说明**：本文原版偏静态，默认某个丢弃函数一旦学会或设计好，就可以持续作为系统优化。但 2026-05-20 的新 index 显示，离线化、缓存、垂直编译层都会遇到同一个动态问题：边界在移动、分布在漂移、缓存会失效。丢弃函数也是对任务分布的压缩，因此需要失效检测、回滚机制和重编译频率模型。否则高效筛选会在新分布下变成系统性盲点。
