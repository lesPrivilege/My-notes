# 编译经济学：智能进步的分层治理框架

> Working Paper · Draft · 2026-05-20
> Source notes: 16 entries from tech.md + mind.md + life.md
> Cluster C: 编译经济学 × 分层治理

---

## 主张

智能进步的核心经济效应不是提升通用能力天花板，而是降低将通用能力「编译」为专用系统的成本。这一过程与生物系统的分层治理架构（硬编码回路处理高频低维任务、智能决策处理低频高维任务）是同一机制的两个投影。竞争的关键指标不是 benchmark 通用能力，而是编译效率。

框架由三条交织的论据链支撑：生物学演示「为什么要分层」，经济学给出「分层的成本判准」，动态性分析揭示「边界如何移动」。

这里的「编译效率」指三类成本的合成指标：把在线推理下沉为离线系统所需的开发时间、部署后节省的边际推理成本、以及分布漂移后重新编译和验证的维护成本。换句话说，竞争优势不只是「能否编译」，而是能否以更低总成本、更短周期、更高正确性，把通用能力转译为稳定的专用执行层。

## 论据链

### E1. 生物学的启示：智能是写在最外层的例外处理

> *来源：tech.md —— 硬編碼回路 vs 智能決策的邊界*

动物的行为大量来自硬编码的控制回路。中枢模式发生器（CPG）驱动步态，固定动作模式（FAP）驱动本能反应，脊髓反射弧甚至不经过大脑。蜜蜂的八字舞、蜘蛛结网、候鸟导航，都是基因写死的程序——输入触发条件，输出固定序列。当前具身智能的「感知→规划→控制」pipeline 与此惊人同构：底层运动靠预编排的轨迹优化或强化学习出来的固定策略，上层套一个有限的决策模块。

关键发现：自然界的解法不是「先实现通用智能再去走路」，而是先用硬编码把运动问题解决到足够好，然后在此基础上慢慢长出灵活的认知层。皮层是后来叠上去的，不是先有皮层再学走路。

**论据功能**：颠覆「通用智能优先」预设。生物进化在「不智能」的阶段已经解决了绝大多数生存所需的计算。

### E2. 通用性与实时性的物理权衡

> *来源：tech.md —— 通用性與實時性物理互斥；生物的解法是分層並行*

硬编码回路的优势恰恰是智能替代不了的：延迟极低、能耗极低、可靠性极高。蛇的攻击反应 60 毫秒，苍蝇的逃逸反射 30 毫秒——这不是「快速思考」，是根本没经过思考，信号在脊髓或神经节层面就闭环了。用 transformer 实时推理出同等精度的运动控制，算力墙就在那里。

这揭示了一个架构层面的根本约束：**通用性和实时性存在物理层面的强权衡**。神经回路越短、越专用，响应越快；越要经过皮层整合、上下文推理，延迟越高。高等动物的解法不是用智能替换本能，而是分层并行——脊髓管步态、脑干管姿态平衡、小脑管协调校准、皮层只在需要改变策略时介入。大部分时间皮层不干预运动。

当前具身智能的困境恰恰是这个分层没做好：要么全走端到端大模型，延迟和能耗扛不住；要么全用传统控制，碰到新情况就死。真正该复刻的不是动物的「智能」，也不是动物的「本能」，而是这个**分层治理的架构本身**——哪些决策该硬编码、哪些该实时推理、边界在哪，这个设计问题可能比模型能力本身更关键。

**论据功能**：给出「为什么要分层」的物理学理由，以及「怎么分层」的架构模板。

### E3. 统一判准：穷举成本 vs 训练成本

> *来源：tech.md —— 劇本化 vs 實時決策的判準*

剧本化 vs 实时决策的判准是任务空间维度，不是任务复杂度。Agent 靠 LLM 做逐步决策既不经济又不稳定，因为 LLM 的失败模式是涌现的而非可预期的。更合理的架构是用 LLM 做一次性剧本生成，把执行层固化——LLM 充当编译器而非运行时。

但「可穷举」的判断本身经常是错的：自动驾驶看似有限场景，组合爆炸后是开放域。所以真正的判准不是「能不能穷举」，而是**「穷举成本是否低于训练成本」**——当穷举成本超过训练成本时，权重就是更经济的剧本存储方式。

这个判准将编程（穷举）、模仿学习（行为克隆）、强化学习（试错搜索）统一到同一经济框架下：三者是同一优化问题的不同边界条件解，差异在于离线固定的比例和时机。

**论据功能**：给出可操作的判准，连接生物分层与工程实现。

### E4. 「能离线解决的不要在线解决」是跨层统一原理

> *来源：tech.md —— 「能離線解決的不要在線解決」是跨層統一原理；life.md —— Chatbot → CLI → Cowork 的三層 pipeline 設計*

从 over-training 把高频 pattern 烧进权重、到 MoE 稀疏激活只调动相关 expert、到 KV cache 命中避免重复 prefill、到 system prompt caching 最大化前缀复用、到 TwELL 的 FFN activation sparsity——每一层都在做同一件事：把重复计算前置，运行时只处理增量。这不是巧合，而是 memory bandwidth 作为硬瓶颈决定了所有抽象层的优化方向必然趋同。

翁的 HL（把自然语言/LLM 推理前置到代码编辑阶段的系统设计）也符合这一原理：运行时不再调用 LLM，而是执行已经生成并固化的代码。但适用边界不是「能不能离线化」，而是「离线化的摊销成本是否低于在线推理的边际成本」。

这个判断也解释了工具链自身的分层：Chatbot 适合 judgment 层的交互式迭代，CLI + Flash 适合结构化重复执行，Cowork 适合产出层的整理和分发。每层选择最经济的 runtime，本质上就是把不同频率、不同不确定性的任务放到不同执行层。

**论据功能**：展示离线/在线原理的普遍性，建立从生物到工程到具体技术的统一视角。

### E5. 边界动态性：判准系统性偏向权重侧

> *来源：tech.md —— 判準邊界動態且系統性偏向權重側；分佈漂移觸發重編譯頻率；CLI/GUI skill 系統分離的維護成本*

「穷举成本 vs 训练成本」的比较是动态的。训练成本在快速下降，穷举成本（本质是领域工程）相对稳定。这意味着今天适合 HL 的任务空间，明年可能就被端到端吃掉——判准成立，但它给出的边界是移动的，而移动方向系统性地偏向权重侧。

这对 HL 的长期投资回报率是一个隐性风险。HL 把 LLM 推理前置到 code edit 阶段，隐含假设是部署时的任务分布和编译时一致。前者的分布漂移由持续训练吸收，后者的分布漂移要靠维护——HL 的摊销模型里少算了这一项：「分布漂移触发的重编译频率」。

维护成本不只来自外部世界漂移，也来自编译层工具链自身。CLI 和 GUI/Cowork 的 skill 系统如果分离存储，就会形成两套需要同步的专用层；这不是运行时推理成本，而是编译产物的版本一致性成本。路径统一之后成本会下降，但这个例子说明：离线化从不免费，只是把成本从推理时刻转移到维护时刻。

这个动态性也是 E1 生物观察的镜像：进化几亿年才把底层控制固化为基因编码，工程解决方案可能需要同样的持续进化过程才能稳定。

**论据功能**：对冲前文偏静态的分析，暴露框架中的动态缺口——既是弱点也是扩展空间。

### E6. LLM-as-compiler 的天花板：正确性判据

> *来源：tech.md —— LLM-as-compiler 天花板在正確性判據*

AGI 的路径不是「一个模型什么都会」，而是「一个模型能为任何领域编写和维护专用系统」。这个「LLM-as-compiler」叙事的天花板在正确性判据：**凡正确性可被程序化验证的领域，LLM-as-compiler 都能走通；正确性依赖隐性判断的领域，仍需各自飞轮。**

边界 case：很多领域的正确性验证本身需要 LLM 参与（代码 review、test 生成）。这时候得到的不是「编译后零 LLM 开销」，而是「编译后低频 LLM 开销用于验证」——架构从 compiler 退化成 compiler + runtime verifier。不致命，但改变了经济学计算。

**论据功能**：勾勒 LLM-as-compiler 的适用范围，给出它的硬天花板。

### E7. 竞争含义：编译效率才是关键指标

> *来源：tech.md —— 智能進步主效應是降低專用系統生產成本；關鍵競爭指標是編譯效率而非 benchmark 通用能力；通用 vs 垂直世界模型與緩存調度同構；mind.md —— 智能進步的元效應*

如果上述框架成立，几个推论值得记下来：

**第一，通用模型的商业价值有天花板，但不是价值消失。** 智能进步的主效应不是让通用层越来越强直到吃掉一切，而是让编译能力越来越强——能把更多原本需要在线推理的问题离线化、固化、下沉到专用层。垂直编译层变厚，通用 fallback 被调用的频率反而降低。通用模型的价值从 runtime rent 转为 compiler rent：它不再主要靠每次任务执行收费，而是靠生产、更新、验证专用系统收费。

**第二，竞争的关键指标不是 benchmark 上的通用能力，而是编译效率。** 同样的任务空间，谁能更快更便宜地把在线推理固化成离线系统，谁就获得了结构性优势。

**第三，真正的护城河在垂直编译层的积累。** 模型可以换，编译出来的领域系统和数据飞轮换不掉。垂直编译层会遇到和缓存系统一样的缓存一致性问题——当物理世界变了（环境变化、硬件迭代），缓存失效的检测和更新机制是什么？生物的方案是让「缓存失效」直接导致个体死亡，由种群层面的遗传变异来更新。工程系统没有这个奢侈，需要主动维护。

**论据功能**：收敛到可操作的结论。给出竞争分析框架和识别护城河的方法。

### E8. 未解决问题

> *来源：tech.md —— 緩存調度類比預測的失效問題；mind.md —— 分層治理 + 離線前置 + 緩存調度框架的未解問題*

1. **动态性缺口**：判准边界在移动、分布在漂移、缓存在失效，框架目前偏静态快照。需要回答：重编译频率的预测模型是什么？
2. **正确性判据的自指问题**：LLM-as-compiler 的验证层如果本身也需要 LLM，经济模型需要修正。
3. **分层接口的耦合度**：三层的层间接口是动态耦合而非静态分层（翁的 HL 论文「已有成熟经验所以不展开」恰好跳过了最不应跳过的部分）。
4. **从几亿年到几年**：进化用几亿年从硬编码走到自主决策，工程上能否找到捷径？目前没有 convincing 的路线图。
