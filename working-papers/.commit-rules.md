# Working Paper Commit/Push Rules

> 此文件定义 working paper 从草稿到入库的成熟度门槛和 git 工作流。
> paper-mill skill 和 CLI 均应遵守。

## 成熟度门槛 (Maturity Gate)

一篇 paper 满足以下条件时标记为 **commit-ready**：

1. **脱敏完成**：所有 E-block 已通过 S/A/U 分级。核心论据链（E1 + 承重 E-block）
   全部为 S 级。不存在 A 级独立 E-block。
2. **泛化完成**：Paper 脱离原始 session context 仍可独立理解。读者无需知道
   "这是哪次对话产出的"即可理解论证链。
3. **无高严重度弱点依赖 A/U 材料**：已知弱点表中，高严重度项不得以"缺乏
   外部验证的个案"为唯一根据。
4. **待补充表状态明确**：U 级剥离产生的验证需求已登记。待补充项的存在
   不阻碍 commit（它们是 Mode C 的输入），但必须已登记。

不满足门槛的 paper 保留在 `working-papers/` 作为 Draft，不 commit。

## 状态标记

Paper 的 header block 中使用以下状态行：

```
> Working Paper · Draft · {date}          ← 未通过门槛
> Working Paper · Commit-ready · {date}   ← 通过门槛，待 commit
> Working Paper · Published · {date}      ← 已 push 到 remote
```

## Git 工作流

### 分工

| 步骤 | 执行者 | 说明 |
|------|--------|------|
| 写文件 / 修订 | Cowork (paper-mill) | 直接写入 `working-papers/` |
| 判定成熟度 | Cowork (paper-mill Mode D 或修订后) | 输出判定结果 + 建议 commit message |
| `git add` + `git commit` | CLI (本地终端) | 使用 Cowork 建议的 commit message |
| `git push` | CLI (本地终端) | 推到 origin/main |

### Cowork 在修订后的输出格式

当 paper 通过成熟度门槛时，Cowork 输出：

```
✅ COMMIT-READY: {filename}
Suggested commit message:
  paper({slug}): {one-line description of change}

  - E-blocks: {N} S-grade, {M} S+A, {K} S←U
  - 待补充: {N} items (non-blocking)
  - Maturity gate: PASS
```

### Commit Message Convention

```
paper({slug}): {verb} {what changed}

Examples:
  paper(compile-economy): initial draft from Mode B assembly
  paper(cognitive-domain-boundary): rewrite E1 for S-grade compliance
  paper(externalization-ceiling): add E13 ceiling/effectiveness axis separation
  paper(discard-capability): revise E1 to reference compile-economy framework
```

## Sync 注意事项

- SKILL.md 的权威版本在本地 plugin 目录，Cowork 不能直接修改
- 如果 Cowork 建议 skill 变更，输出 diff 后由 CLI 在本地替换
- `working-papers/` 的文件 Cowork 可以直接读写
- `usage-index.md` 由 Cowork 维护，commit 时一起入库
