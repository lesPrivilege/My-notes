# Externalization Ceiling: Harness 层投资的结构性贬值

> Working Paper · Draft · 2026-04-30 (rewritten 2026-05-12)
> Source notes: 8 entries from tech.md, power.md, mind.md

---

## 主张

当前 AI 工程中所有不修改模型权重的改进——prompt engineering、harness 框架、managed agents、alignment monitoring——本质上是同一件事：externalization。这类改进的天花板不是来自工程努力不足，而是来自模型底层表征的几何结构，后者由训练目标（有损压缩）雕刻，不为使用需求服务。由此推出一个可操作的推论：harness 层的投资必然随模型进步而贬值，其价值上限与模型商品化程度呈负相关。变薄是收敛方向，变厚是有窗口期的追赶策略。

## 论据链

### E1. 统一归类：所有 harness 改进都是同一件事

> *来源：tech.md —— 外化的天花板*

当前 AI 工程所有改进（prompt / harness / managed agents / alignment monitoring）本质都是同一件事：externalization——在不改变模型权重的前提下重组外部运行时环境。天花板不来自工程努力不足，而来自模型底层表征的几何结构，后者由训练目标（有损压缩）雕刻，不为使用需求服务。

**论据功能**：建立分析的统一框架。将分散的工程活动归为同一类别后，才能讨论它们共享的结构性限制。

### E2. 每个 harness 组件都是对特定缺陷的临时补丁

> *来源：tech.md —— Harness 是临时补丁*

每个 harness 组件都是对当前模型某个缺陷的补丁。Anthropic 为 Sonnet 4.5 的 context anxiety 设计的 reset，在 Opus 4.5 变成死代码——证明 harness 的保质期就是下一次模型更新的时间。

**论据功能**：提供可观察的经验事实。harness 组件因模型更新而失效不是推测，是有具体案例支撑的观察（context anxiety reset → dead code）。

### E3. Harness 生命周期由模型进步速度决定，不由工程质量决定

> *来源：tech.md —— Harness 的保质期是下一次模型更新*

Cat Wu 团队每次新模型发布就通读 system prompt 并移除多余指令，to-do list 追踪工具在模型能力上来后被废弃——这不是产品迭代，而是脚手架拆除。Harness 的合理生命周期不由自身的工程质量决定，而由底层模型的进步速度决定。投入在 harness 上的资源本质上是在给一个会缩水的资产加杠杆。

**论据功能**：将 E2 的单点观察提升为结构性判断。harness 的贬值速度是外生的（由模型侧决定），不是内生的（由 harness 质量决定）——这意味着无论 harness 工程做得多好，都无法控制自身的保质期。

### E4. 变薄与变厚是位置函数，变厚策略有内在矛盾

> *来源：tech.md —— Harness 变薄与变厚是位置函数，不是路线分歧*

Anthropic 说 harness 应该变薄，小米说 harness 应该变厚，两者都对但不对称。Anthropic 站在模型前沿，看到的是 harness 的递减价值；小米站在追赶期，看到的是 harness 的当下杠杆。关键在于：变厚策略有内在矛盾——你投入越多资源在框架上，模型进步越快让这些投入贬值。变薄策略没有这个矛盾，因此是收敛方向。

**论据功能**：化解表面矛盾（「应该变薄」vs「应该变厚」），将其重新描述为位置依赖的策略选择。核心贡献是指出变厚策略的自毁性：投入越多 → 模型进步越快（部分受益于 harness 层的数据/反馈）→ 投入贬值越快。变薄策略不触发这个循环。

### E5. Harness 价值天花板与模型 commodity 化是硬币的两面

> *来源：power.md —— Harness 层的价值天花板与模型层的 commodity 化是同一枚硬币的两面*

当模型趋向 commodity，externalization（prompt/harness/orchestration）的价值上升——但 externalization ceiling 论证的是这个价值有天花板。两个判断合起来意味着：客户端+运行时的护城河真实存在但不是无限深的。Anthropic 的赌注是在天花板到来之前，用 governance 控件和企业级粘性把护城河加固到足够深。

**论据功能**：从商业战略视角补完论证。模型 commodity 化 → harness 价值上升（对冲 E1-E3 的贬值趋势），但这个上升有 ceiling。Anthropic 的策略被描述为「与时间赛跑」：在模型侧的天花板压下来之前，用非技术维度加固护城河。

### E6. 蒸馏创造静态分身，不是成长

> *来源：mind.md —— 蒸馏的悖论*

从个人记录中完美蒸馏出的技能，本质上是复制了其过往的输出模式。这种「成功」的复制反而塑造了一个无法成长的静态分身，因为它剥离了人类对自我过往判断至关重要的批判性距离与反思能力。

**论据功能**：从认知维度揭示 externalization 的更深一层限制。不仅 harness 是对模型缺陷的补丁，从人类经验中蒸馏出的工作流本身也是静态快照——完美复制了输出模式，但丢失了生成这些模式的反思过程。这为 E1 的「天花板来自表征几何」提供了认知侧的同构论证。

### E7. 工作流显性化是线性扩展，与模型飞轮形成结构性对比

> *来源：tech.md —— 工作流显性化的线性扩展结构*

Prompt engineering 的真实上限不是写 prompt 的技巧，而是提取者对目标领域默会工作流的理解深度。每个领域需要单独做一次深度工作流提取，产出的系统提示不能迁移，提取质量取决于同时具备领域实践深度和形式化能力的人——这个交集极小。扩展路径因此是线性而非指数的，与 LLM 主线的飞轮效应形成结构性对比。

**论据功能**：量化 externalization 的扩展瓶颈。模型侧有飞轮效应（数据 → 训练 → 能力 → 更多数据），harness 侧是线性扩展（每个领域单独提取，不能迁移）。这个不对称决定了：即使某个时刻 harness 的价值很高，其扩展速度也无法匹配模型侧的指数改进。

### E8. Harness 作为负空间地图——模型能力等高线的持续绘制

> *来源：tech.md —— Harness 是模型能力的负空间地图*

上游厂商公开的工作流和产品设计选择，其价值不在工作流本身的精巧，而在于它们暴露了厂商认为模型当前能可靠执行的边界在哪里。Cat Wu 团队每次新模型发版后通读 system prompt 移除模型不再需要提醒的部分，这个操作本身就是在持续绘制模型能力的等高线——被拆掉的脚手架标记了模型已经内化的能力，保留的脚手架标记了仍需外部补偿的缺陷。

这意味着 harness 不只是功能性的补丁层，它同时是一个**诊断工具**：harness 的内容和变迁记录了下游对模型能力边界的最佳估计。当观察到某个 harness 组件被移除（如 Sonnet 4.5 的 context anxiety reset 在 Opus 4.5 中消失），你就知道模型在该维度上越过了 threshold。这种诊断价值不受 harness 本身贬值的影响——即使 harness 组件因模型进步而被拆除，其曾存在的记录本身就是有价值的信息。

**论据功能**：翻转视角。前面 E1-E7 论证 harness 因模型进步而贬值，E8 指出 harness 的历史记录（哪些被拆了、哪些留下了）本身是一个关于模型能力边界的可追踪信号。这个诊断价值**不随 harness 贬值而消失**——组件被拆除的事实正是最有信息量的信号。这为 W5（harness 的非贬值价值）提供了一条具体机制。

## 已知弱点

### W1. 「表征几何」是隐喻，不是可测量的变量

E1 声称天花板来自「模型底层表征的几何结构」，但这是一个不可直接观测的隐喻。当前没有任何论文给出「表征几何」的可操作定义或测量方法。整个论证链的根基是一个黑箱——我们知道天花板存在（E2 提供了经验案例），但无法精确定位它在哪里、移动速度有多快。

**严重程度**：中。论证的结论（harness 会贬值）有 E2 的经验支撑，但贬值的「原因」部分停留在隐喻层面。

### W2. 变薄策略的时间维度被忽略

E4 论证变厚策略有内在矛盾，变薄是收敛方向。但对于追赶期的厂商，变厚可能是唯一可行的过渡策略——问题不是「变厚对不对」，而是「变厚能维持多久」。论证没有给出变厚→变薄的切换时机判据。

**严重程度**：中。对追赶者而言，「变薄是收敛方向」是正确的但不可操作——你不能在模型能力不足时就拆掉脚手架。

### W3. E5 的 ceiling 来源不够具体

E5 引用 externalization ceiling 但未展开其具体论证。Ceiling 到底来自什么？是 harness 效益的边际递减？模型能力提升消解了 harness 要解决的问题？还是企业客户的支付意愿上限？三者的政策含义不同。

**严重程度**：高。这是论证链中最模糊的一环。

### W4. E6 的蒸馏悖论是认知隐喻，技术映射不完整

E6 来自认知哲学笔记，讨论的是「从个人记录中蒸馏技能」。将其映射到 AI harness 层是一个类比——蒸馏出的工作流像蒸馏出的个人技能一样是「静态分身」。但这个映射缺少技术层面的验证：system prompt 真的像个人技能蒸馏一样「剥离了批判性距离」吗？还是只是「过时」？

**严重程度**：中。隐喻有启发性但不是论证。

### W5. Harness 的非贬值价值被低估

E8 部分地回应了这个弱点，但论证聚焦于 harness 的技术贬值，忽略了某些维度的价值可能不随模型进步而消失：
- **合规与治理**（audit trail、policy enforcement）——制度需求，不因模型变强而消失
- **可观测性**（logging、tracing）——运行时基础设施的需要独立于模型能力
- **多模型编排**——当底层模型频繁切换时，统一接口层的价值反而上升
- **诊断记录**（E8）——哪个 harness 被拆了的历史本身就是信号

**严重程度**：高。可能从根本上修改结论——harness 的技术补丁价值确实会贬值，但其基础设施和诊断价值可能具有持久性。
